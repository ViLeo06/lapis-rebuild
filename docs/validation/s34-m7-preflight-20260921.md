## Preflight conflict map

### C1 — M6 promotion thresholds conflict with M7

Current M6 profession policies promote at `10 / 20 / 30 / ...`. M7 requires the first seven stages to follow `6 / 16 / 26 / 36 / 46 / 56`.

Integration rule: do not patch the M6 profession modules before S31/S32 handoff is available. S34 will consume their stage resolver/policy if provided; otherwise S34 will apply the smallest shared policy patch and retain stages 8-10 without deleting M6 capability.

### C2 — M6 representative skill availability conflicts with staged unlocks

Current M6 swordsman and wizard adapters deliberately keep the three M5.1 representative skills available from the initial stage. M7 requires one new skill per stage and Skill Lv1-Lv6.

Integration rule: S31/S32 become the profession skill authorities. M6 authored class rows, visual families and SaveV2 stage data remain evidence inputs, not the M7 skill-unlock authority.

### C3 — shared battle core

M7 adds DOT, stun, petrify, healing block, periodic self-damage, recovery actions and fixed-level monster abilities. The shared core touch points are `web/src/battle.ts`, `web/src/scene.ts` and `web/src/main.ts`.

Integration rule: only S34 patches those files. Prefer S30-S33 adapters/status modules and keep numerical policies outside shared core.

### C4 — SaveV2 extension

M6 persists stage, quest, equipment and progression. M7 additionally requires skill unlock/level state and HP/MP consistency while Developer override must not contaminate normal saves.

Integration rule: preserve accepted M5.1/M6 migration and extend through existing SaveV2/M6 extension boundaries. Debug preset state is transient unless explicitly saved as a debug profile.

### C5 — training camp and battle scenes

S33 will own 15 battle presets and UI. S30 will own monster catalog/difficulty data.

Integration rule: S34 must verify every preset resolves to fixed monster definitions and scene resources. Dynamic Easy/Normal/Hard/Very Hard is display-only; enemy level/stats/AI must not scale with player level.

### C6 — inherited player input gates

M5.1 accepted pointer NPC interaction, keyboard E, phone touch, delayed camera centering, map-edge clamp and confirmed retreat.

Integration rule: M7 cannot close if any inherited input gate regresses, even if new combat unit tests pass.
