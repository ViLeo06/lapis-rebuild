## 采集顺序

### A. 场景与战斗入口

- 记录客户端版本证据、场景/地图可读名称、战斗前后 HUD 差异、队伍人数与单位职业/等级（不记录账号名）。
- 若当前战斗已在进行，先保存一帧起始态：双方位置、单位可见名称/外形、状态栏、地图小图、可选操作与胜负目标。
- 记录本次可见战斗场景/可见 zone 与地图标识；不外推 field-map→battle-zone 的通用规则。

### B. 行动槽与单步操作

对每一条观察分别记录：行动前 readiness/状态、唯一操作、操作后槽值/位置/HP/MP、截图索引、观察间隔与是否有其他变量变化。

1. 被动观察满槽或恢复中的显示与可行动门禁；只在刷新节奏可读时估计间隔，并将帧率/网络延迟作为混杂因素。
2. 若界面和资源许可，分别单次测试 MOVE、普攻、REST、一个低风险技能；每次先留行动前帧，再执行一次并立即刷新。
3. 对 MOVE 记录合法格、起终格、移动范围、方向、越障/占位结果；对普攻/技能记录目标距离、提示范围、选中反馈、MP 与 readiness 变化。
4. 不自动连点，不刷道具，不以重复同一目标来推算大样本概率。

### C. 命中、AI 与表现

- 观察敌方回合：等待/移动/普攻/技能的可见次序、可用目标、行动槽变化、结束回合条件。
- 对每次 HP/MP 变化记录操作前后值、是否出现 miss/critical/受击/施法/死亡表现、文本提示与声音（声音仅文字描述）。
- 单次对照不能推出 hit/damage/critical/defence 公式；UI 数值与屏幕动画分开记录，server-authoritative HP 的判断只在有重复证据或协议材料时升级。
- 对动画只登记动作/帧切换/可见停顿；raw ANI timing、impact frame、MagicRes placement 和 occlusion 仍由静态证据另行验证。

### D. 结算与返回

- 若当前战斗自然完成，记录胜负条件、结算面板可见字段、奖励显示、队伍状态和返回路径；不强行刷战或复位。
- 若存在角色死亡、消耗不可再生资源、付费、交易或存档覆盖风险，则停止于该分支并记录未观测原因。
- “剧情/战斗已选择”与“实际 battle scene 已进入”、“画面显示奖励”与“服务器已持久化奖励”分别记录。

## 采集停止条件

- 窗口变成登录、权限、更新或安全提示；出现未知弹窗。
- Windows 桌面进入锁屏；由用户手动解锁后，再重新列举应用/窗口并获取新截图。
- 动作可能影响真实账号进度、不可再生资产、付费/交易或不可回滚存档。
- 同一观测要求跨多个变量或结论只能靠猜测；先记录 `UNVERIFIED` 并回到静态/历史资料。
- UI 操作后截图刷新失败或状态不明确；先重新只读观察，不盲目重试。
