# `.ani` 格式研究记录

> 状态：结构层已突破，动作语义继续验证  
> 更新：2026-09-15

## 1. 结论

已对客户端内 **6,948 个 `.ani`** 文件完成静态结构统计，并对剑士、巫师目标职业 **100 组 `.ani + .spr`** 做了严格交叉验证。

当前可以把 `.ani` 的结构层视为已突破：

- 全部样本文件长度均为 **1,236 字节**；
- 全部样本 `layer_count = 1`；
- 已确认动作文件中存在固定的 8 个方向槽；
- 已确认每个方向最多预留 32 个帧索引，但**只有前 `frames_per_direction` 项有效**；
- 剩余槽位可能保留生成器旧内存/脏数据，不能当成动画帧；
- 剑士/巫师 100 个目标资源中，所有有效帧索引都能严格落入配套 `.spr` 的真实帧范围内，错误数为 0。

尚未完全确认的是：动作文件后部 `float32` 字段的精确时间单位、动作循环规则，以及文件后缀 `_00/_01/...` 与运行时状态的最终语义绑定。这些进入 M2 行为基准验证。

## 2. 固定布局

所有 6,948 个样本均符合以下基本布局：

| 偏移 | 长度 | 类型 | 当前解释 | 证据级别 |
| ---: | ---: | --- | --- | --- |
| `0x000` | 64 | `char[64]` | 生成器/源动画说明文本，常见 CP949 韩文 | 已验证 |
| `0x040` | 4 | `uint32 LE` | `layer_count`，当前全部为 1 | 已验证 |
| `0x044` | 64 | `char[64]` | 图层名称，角色多为 `Body_`，MagicRes 可见 `FOCUS/_FOCUS` | 已验证 |
| `0x084` | 4 | `uint32 LE` | `frames_per_direction` | 已验证 |
| `0x088` | 1024 | `uint32[8][32] LE` | 8 个方向，每方向预留 32 个帧索引 | 已验证 |
| `0x488` | 4 | `float32 LE` | 时间/速度相关原始值，单位仍待行为验证 | 结构已验证、语义待验证 |
| `0x48c` | 4 | `uint32 LE` | 保留值，当前观察为 0 | 已验证 |
| `0x490` | 68 | bytes | 保留/生成器残留区，不作为动画数据解析 | 已验证为非活动区 |
| `0x4d4` | - | - | 文件结束 | 已验证 |

### 2.1 最重要的解析规则

对于方向 `d`：

```text
base = 0x088 + d * 0x80
valid_frames = uint32[frames_per_direction] from base
```

每个方向后续未使用的槽位必须忽略。

这条规则解决了此前在部分高阶职业资源上看到“帧号超过 `.spr` 帧数”的假异常。例如某些文件 `frames_per_direction = 4`，每个方向前 4 项都完全有效，而第 5～32 项会出现 100 以上的旧值；这些值不是当前动画帧。

## 4. 剑士/巫师目标资源验证

已针对：

- 剑士：`B100/B110/.../B190`
- 巫师：`B109/B119/.../B199`
- 动作后缀：`_00/_01/_02/_03/_05`

共验证 **100 组 `.ani + .spr`**。

结果：

- `.ani` 可解析：100 / 100
- `.spr` 可完整解析：100 / 100
- ANI 有效帧索引全部在对应 SPR `[0, frame_count)`：100 / 100
- SPR 每帧 payload 长度、行数、span 边界和文件尾一致：100 / 100
- 严格验证错误：0

目标资源中的 `frames_per_direction` 主要为 4，也存在 5、6、7、8、10、11；原始时间/速度值主要为 5.0，少量为 7.0 或 10.0。

## 5. 动作后缀与方向：当前解释

通过实际导出的序列图，可以得到以下**高概率**映射：

- `_00`：待机 / idle
- `_01`：移动 / walk
- `_02`：普通攻击或施法攻击 / attack-cast
- `_03`：受击 / hit reaction
- `_05`：职业/动作特有序列，不能统一解释为死亡

尤其是巫师 `B109_05` 含较长特殊序列，因此已经排除“所有 `_05` 都是 death”的简单假设。

8 个方向槽当前视觉推断为：

| 槽位 | 高概率朝向 |
| ---: | --- |
| 0 | 南 |
| 1 | 东南 |
| 2 | 东 |
| 3 | 东北 |
| 4 | 北 |
| 5 | 西北 |
| 6 | 西 |
| 7 | 西南 |

方向顺序已经得到角色视觉姿态支持，但最终仍需在 M2 中通过实际地图坐标与移动输入确认。

## 6. 解析工具

正式解析器：

- `tools/convert/ani.py`
- `tools/convert/spr.py`
- `tools/validate/validate_character_assets.py`

旧的 `ani_probe.py` 保留为考古/未知变体探针，不再作为已知格式的生产解析器。

生产解析器必须：

1. 保留原始 header/layer 文本与字节值；
2. 只返回每个方向前 `frames_per_direction` 个有效帧；
3. 可选读取配套 `.spr` 帧数并进行严格边界校验；
4. 对异常文件显式失败，不静默修补；
5. 保留 `0x488` 原始浮点值，不提前换算成未经验证的时间单位。

## 7. 后续验证门

### ANI-1：记录边界

**已通过。** 6,948 个文件结构高度一致。

### ANI-2：帧索引

**已通过。** 100 个目标职业 ANI/SPR 对全部严格通过索引边界验证，并已生成实际动作预览。

### ANI-3：动作与方向语义

**部分通过。** `_00/_01/_02/_03` 已有较强视觉证据；`_05` 明确为多义/职业特有动作。8 方向顺序为高概率结论，待 M2 最终确认。

### ANI-4：时间与循环

**待 M2。** `0x488` 已定位，但时间单位与循环规则需要实际客户端行为录像/测量支撑。

## 8. 边界

当前结论来自资源结构和视觉帧连续性，足以进入 M1 后续资源工作与 Godot 原型准备；但在没有行为基准前，不把“播放多少毫秒”“哪个动作一定循环”“哪个后缀一定对应死亡”写死到游戏规则中。
