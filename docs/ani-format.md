# `.ani` 格式研究记录

> 状态：进行中  
> 更新：2026-09-15  
> 证据级别：当前仅确认“存在固定长度动作/帧索引结构”；具体字段语义仍待真实样本验证。

## 目标

恢复 NeoDark / Lapis 客户端 `.ani` 文件中的：

- 动作编号；
- 方向编号；
- 帧索引序列；
- 单帧或整段播放时长；
- 循环规则；
- 与配套 `.spr` 帧资源之间的映射；
- 可能存在的锚点、偏移或事件标记。

最终输出需能稳定生成：

```json
{
  "action": "walk",
  "direction": 0,
  "frames": [12, 13, 14, 15],
  "durations_ms": [100, 100, 100, 100],
  "loop": true
}
```

上面的字段只是目标中间格式示例，不代表已经确认原始 `.ani` 的真实字段布局。

## 当前已知

1. 现有客户端分析已观察到 `.ani` 呈固定长度记录特征。
2. 尚无足够证据把任何字节位置直接命名为 `action`、`direction`、`frame` 或 `duration`。
3. `.spr` 已经能够解出实际图像帧，因此 `.ani` 最重要的交叉验证条件是：候选帧索引必须落在配套 `.spr` 的真实帧数量范围内。
4. 不应因为文件长度能被 4/8/16 等尺寸整除，就自动认定某一尺寸是真实记录宽度。

## 本轮加入的探针

`tools/convert/ani_probe.py` 用于第一阶段结构统计：

- 记录文件大小与 SHA-256；
- 计算字节熵；
- 输出头尾 64 字节十六进制；
- 对多个候选记录宽度做整除、重复记录、全零记录统计；
- 可结合配套 `.spr` 帧数量，观察按 little-endian `uint16` / `uint32` 解释后的值域命中率；
- 用户明确指定候选记录宽度后，输出各记录的原始 hex、`u16/i16/u32/i32` 解释，保留原始 offset。

注意：探针评分只用于缩小人工检查范围，不构成格式证据。

## 验证路线

### Gate ANI-1：记录边界

至少选取 10 个不同职业/动作相关 `.ani`：

- 比较文件总长度；
- 查找共同头部、尾部与重复块；
- 检查候选记录宽度在多文件间是否稳定；
- 排除仅由“刚好整除”造成的假阳性。

通过条件：同类文件中存在稳定记录边界，并能解释绝大多数文件而非单一样本。

### Gate ANI-2：帧索引

对每个 `.ani` 找到配套 `.spr`：

- 得到 `.spr` 实际帧数 `N`；
- 检查候选字段是否主要落在 `[0, N)`；
- 把候选序列渲染为联系表或 GIF；
- 肉眼验证是否出现连续的行走、攻击、受击、施法等动作。

通过条件：至少 3 个角色资源上，候选帧字段可形成视觉上连续且可重复的动作。

### Gate ANI-3：动作与方向分组

比较剑士与巫师资源：

- 识别固定数量的动作块；
- 识别每个动作块中的方向数量；
- 不预设四方向或八方向；
- 使用镜像关系、角色朝向和帧连续性验证方向编号。

通过条件：至少能稳定标出 `idle / walk / attack / hit / cast / death` 六类中的四类，并说明证据。

### Gate ANI-4：时间与循环

若记录中存在疑似时间字段：

- 比较同一动作各帧的数值规律；
- 结合客户端录像或后继 Lapis 行为测量；
- 区分“毫秒”“tick”“帧数”“固定常数”等可能解释。

通过条件：生成的动画速度与参考客户端视觉行为基本一致。

## 样本最小集合

优先收集：

- 剑士 `100` 初始阶段；
- 剑士 `190` 最高阶段；
- 巫师 `109` 初始阶段；
- 巫师 `199` 最高阶段；
- 至少一个怪物；
- 至少一个 NPC；
- 至少一个技能/特效相关动画文件。

每个样本同时记录配套 `.spr` 路径、帧数、SHA-256 和来源客户端版本。
